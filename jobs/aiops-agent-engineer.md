# 运维智能体开发工程师(AIOps Agent)职位描述(JD)

## 岗位基本信息
- **岗位名称**：运维智能体开发工程师(AIOps Agent Engineer / SRE Agent研发工程师)
- **岗位定位**：运维智能化层 - 智能体驱动的自主运维体系建设
- **工作性质**：全职
- **工作地点**：杭州/北京/深圳/上海
- **招聘人数**：若干
- **薪资范围**：35K-80K/月
- **团队规模**：智能运维团队15-80人，Agent方向小组5-15人

## 公司与行业背景

### 行业背景
大模型推动运维行业从"AIOps 1.0"(异常检测/告警收敛等单点算法)迈入"AIOps 2.0"(智能体自主运维)时代。运维智能体以LLM为推理核心，通过工具调用(诊断命令、监控查询、变更执行)完成告警研判、根因定位、方案推荐乃至受控自愈的闭环。头部云厂商已将SRE Agent应用于容器服务、数据库等产品线的值班辅助与工单处理，故障平均恢复时间(MTTR)显著下降。该岗位要求"K8s/云平台运维Know-How + Agent工程能力 + 语料工程方法论"三位一体，是2026年运维领域薪资溢价最高的复合型岗位。

## 岗位职责

### 运维智能体架构设计与开发
- 负责SRE运维智能体的整体架构设计(规划-推理-工具调用-反思循环)
- 开发告警研判、故障诊断、根因分析、方案推荐等核心Agent能力
- 设计多Agent协作机制(诊断Agent/变更Agent/值班Agent分工编排)
- 建设Agent安全护栏(高危操作拦截、权限分级、人工确认机制)
- 优化Agent的推理链路(上下文管理、长任务规划、失败重试)

### 运维工具体系与Skills封装
- 将K8s/ACK诊断能力封装为标准化工具(kubectl诊断、日志检索、指标查询)
- 建设基于MCP等协议的运维工具生态(工具注册、鉴权、审计)
- 设计Skills规范：将SOP/排障手册转化为智能体可执行的技能单元
- 建设工具执行沙箱与只读/写操作分级管控
- 沉淀可复用的诊断工作流(如节点异常、Pod异常、网络异常诊断树)

### 语料工程与知识建设
- 主导故障案例、工单记录、排障过程的结构化语料化处理
- 设计运维语料Schema(现象-诊断路径-根因-解法-验证的结构化表达)
- 建设RAG运维知识库(文档切分、向量检索、知识更新机制)
- 构建SFT训练语料与偏好数据(面向运维垂域模型微调)
- 建立语料质量评估标准与清洗流水线

### 效果评测与持续优化
- 设计Agent评测体系(诊断准确率、工具调用成功率、MTTR改善)
- 建设离线评测集(基于历史故障案例回放)与在线A/B机制
- 分析Bad Case并驱动Prompt/工具/语料/模型的迭代优化
- 输出智能体运营数据报表与价值度量

### 场景落地与推广
- 推动智能体在值班辅助、工单预诊断、变更风险分析等场景落地
- 与SRE团队协作收集反馈并持续改进人机协作体验
- 建设ChatOps入口(钉钉/飞书机器人)与工单系统集成

## 面试准备建议

### 高频面试题
1. **Agent架构**：设计一个K8s故障诊断Agent，如何划分规划、工具调用与反思环节？如何控制诊断步数与成本？
2. **工具设计**：把"节点NotReady排查SOP"封装为Agent工具集，工具粒度如何取舍？粗粒度诊断树与细粒度原子命令各有什么利弊？
3. **语料工程**：一条原始工单(对话+操作记录)如何加工成高质量语料？Schema应包含哪些字段？如何保证脱敏与质量？
4. **幻觉治理**：Agent给出了看似合理但错误的根因结论，如何从检索、工具证据链、置信度表达三个层面缓解？
5. **评测体系**：如何证明智能体"真的有用"？离线评测集如何构建？MTTR归因如何剔除混杂因素？
6. **安全护栏**：Agent建议执行"重启节点"，如何设计分级审批与爆炸半径控制？

### 系统设计题
- 设计一个多Agent协作的值班助手(告警研判→诊断→通报→复盘草稿)
- 设计运维Skills的全生命周期管理体系(开发/测试/发布/度量/退役)
- 设计故障案例语料库的Schema与自动化采集流水线
- 设计MCP工具网关(注册/鉴权/限流/审计)

### 实操考察
- 现场编写Prompt完成一个告警研判任务并解释设计思路
- Python实现一个简单的工具调用循环(含错误处理)
- 分析一段真实排障记录，抽取结构化诊断路径
