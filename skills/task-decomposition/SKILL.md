# 任务拆解

用户的描述经常是结果（"做个导出功能"），不是任务。本技能把结果转成可执行、可验收的步骤序列。

## 步骤

1. **复述目标**：用一句话说出"做成什么样算完成"。说不出就先向用户提问（一次一个问题），不要开始猜。
2. **列出验收标准**：每条必须是客观可检查的（测试通过 / 页面行为 / 构建结果）。出现"更好""优化"这类词就追问其可观察的定义。
3. **拆步骤**：每步满足——
   - 单一意图（一个提交能承载）
   - 有独立验收标准
   - 完成后系统处于可运行状态
   - 步骤间依赖显式（标注依赖哪个前置步骤）
4. **标注风险与检查点**：哪些步骤有破坏性（改接口/数据迁移），哪几步之后需要人确认再继续。
5. **输出计划**：步骤列表 + 每步验收标准 + 检查点位置，请用户确认后再执行第 1 步。

## 输出格式

```
目标：<一句话>
验收标准：1..n
步骤：
  S1 <动作>（验收：<标准>）
  S2 <动作>（依赖 S1；验收：<标准>）
检查点：S2 后人工确认；S4 涉及 schema 变更，执行前需批准
非目标：<本次不做>
```

## 禁止

- 把"实现 + 测试 + 文档 + 部署"塞进一个步骤。
- 在用户确认计划前写任何实现代码。
- 拆出的步骤依赖"到时候再想"——每个步骤必须有当下可写的验收标准。
