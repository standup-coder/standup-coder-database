# 小程序运营与增长

小程序的增长逻辑和 App 是两套：**没有应用商店可买量，没有 ASO 关键词池可蹭，用户不会主动"打开"一个小程序**。流量几乎全部来自平台内分发（搜一搜、附近、场景入口）和社交关系（群、分享、公众号）。所以 OPC 做小程序运营，本质是两件工作：**把平台白送的入口一个个占掉**，以及**让每个进来的用户有理由把卡片再发出去**。

数据字段与埋点口径见 [03-operations.md](./03-operations.md)；变现动作见 [05-monetization.md](./05-monetization.md)；本篇所有裂变玩法都受"诱导分享"红线约束，红线详见 [06-legal.md](./06-legal.md)。

## 本篇结构

```
入口层   → 平台内流量入口全景、搜一搜、公众号联动、附近的小程序
拉新层   → 冷启动四招、推广渠道、付费投放（微信站内位与广告、抖音巨量引擎）
传播层   → 分享裂变机制、裂变活动 SOP、口碑传播落点、抖音内容运营
留存层   → 订阅消息、私域承接与工具最小栈、客服与 Churn 治理
度量层   → 增长仪表盘、A/B 测试、瓶颈诊断与健康度自测
平台层   → 支付宝运营能力（生活号、卡券、场景绑定）
风险层   → 失败模式对照、渠道集中度自检、社群调研数据的正确用法
```

## 1. 平台内流量入口全景

**【专题补写】** 这是本专题对 OPC 最有价值的一张表：小程序流量入口不由你买，由平台分配，而你**能主动配置的只有下面这几列**。逐条对着做，通常能在零预算下拿到第一波稳定流量。

```
微信：
├── 搜一搜（名称/描述/标签/服务直连）        ← 可配置，见第 2 节
├── 群聊与好友分享卡片                        ← 靠 onShareAppMessage，见第 5 节
├── 朋友圈（只能通过小程序码/广告/海报间接进入）
├── 公众号（菜单、文章内嵌、关注回复、模板消息）← 可配置，见第 3 节
├── 附近的小程序（有实体店才有效）              ← 可开通，见第 4 节
├── 我的小程序 / 下拉任务栏                    ← 靠用户主动添加，诱导添加是红线
├── 小程序广告（Banner、激励视频、朋友圈广告）  ← 付费，见第 6 节
├── 外部 App 拉起（URL Scheme / 开放标签）      ← 见 02
└── 扫码（小程序码、带参数太阳码）              ← 线下场景主力
```

> 微信站内推广清单来自 `../super-individual/app-publishing-guide/mini-program/wechat.md:549-580`，本节按可操作粒度扩写。

```
抖音（逻辑完全不同：内容即入口）：
├── 视频挂载（视频下方小程序入口 + 评论区入口）
├── 搜索（名称搜索、关键词搜索）
├── 个人主页（抖音号绑定小程序后主页有入口）
├── 直播（直播间挂载、购物组件）
└── 话题页入口

# 抖音特色：
# 优质内容可直接带动小程序访问
# 适合：
# - 内容电商
# - 工具类小程序
# - 娱乐类小程序
```

> 来源：`../super-individual/app-publishing-guide/mini-program/douyin.md:285-320`

```
支付宝：
├── 搜索（支付宝首页搜索框权重高）
├── 首页推荐位 / 小程序应用列表（平台按使用频次与场景分配）
├── 生活号（内容位，见第 12 节）
├── 卡包 / 会员卡 / 优惠券
├── 支付成功页（有交易场景才有，转化质量极高）
└── 扫码
```

**【专题补写】** 三平台入口结构差异决定运营投入方向：

| 维度 | 微信小程序 | 抖音小程序 | 支付宝小程序 |
|------|-----------|-----------|-------------|
| 主入口 | 社交分享 + 搜一搜 | 短视频/直播挂载 | 搜索 + 支付场景 |
| 内容生产要求 | 低（图文即可） | 高（必须持续出片） | 中（生活号） |
| 流量可预测性 | 中（受分享链路波动） | 低（爆款驱动） | 中（场景稳定） |
| 单次访问质量 | 中高（熟人推荐） | 低到中（内容冲动） | 高（带着交易目的来） |
| OPC 该把时间放哪 | 分享机制 + 搜一搜 | 视频产能 | 场景绑定与卡券 |

## 2. 搜一搜优化

```
# 名称优化：
- 名称包含关键词
- 早注册占位

# 描述优化：
- 描述包含关键词
- 说明核心功能

# 标签设置：
- 设置相关标签
```

> 来源：`../super-individual/app-publishing-guide/mini-program/wechat.md:534-548`

**【专题补写】** 原文只有五条要点，实际执行要按下面这样展开。搜一搜是小程序唯一"长期不需要维护也能来量"的入口，值得花一整天做透。

```
Step 1：定关键词（先查再改，不要凭感觉）
├── 在微信搜一搜里输入你的品类词，看下拉联想词 → 这就是真实搜索量
├── 看结果页前 10 名是谁，它们的名称/简介怎么写的
├── 分三类记录：
│   ├── 品类词（如"记账""排班""题库"）—— 竞争激烈但量大
│   ├── 场景词（如"工地考勤""宠物免疫本"）—— 竞争小，转化准
│   └── 品牌词（你的名字 + 别名）—— 防止别人占位
└── OPC 策略：名称里塞一个精准场景词，不要抢品类大词
    原因：品类大词你排不过老小程序，场景词能排到且用户意图明确

Step 2：名称
├── 格式建议："品牌名 + 一个核心功能词"
├── 名称一年改动成本高（涉及审核与用户认知），一次定准
├── 不要堆砌关键词，会被判定为不规范命名而驳回
└── 名称唯一性：主体下同名需处理，注册前先在搜一搜查一遍

Step 3：简介
├── 一句话覆盖"谁 + 用来做什么 + 差异点"
├── 把 Step 1 里的场景词自然写进去，不要重复堆词
└── 前 20 字最关键（结果页只露出前面）

Step 4：标签与服务直连
├── 标签：填平台给出的类目相关标签，宁精勿多
└── 页面路径收录：后台可提交小程序内页面供搜一搜索引，
    把内容型页面（列表详情、模板页、结果页）提交上去，
    这比只有首页被索引能多带来数倍长尾流量

Step 5：把"使用人数"做起来
├── 搜一搜排序里，使用量与完成率是重要因子
└── 结论：搜一搜不是文案活，是产品活。
    先把激活率和 7 日回访做上来，排名会自己往上走
```

> 政策快照｜截至 2026 年 10 月。平台规则会调整，发布前请核对官方文档，以官方为准。

**【专题补写】** 原文 `wechat.md:555` 对公众号联动只写了"公众号关联"一行，这是微信小程序最值得补齐的一块——**同主体公众号是 OPC 唯一免费、可反复触达、且能直接嵌小程序的自有阵地**。八个联动位：

```
1. 公众号菜单直挂小程序          → 三个菜单项至少留一个
2. 图文文章内嵌小程序卡片        → 每篇文章正文中部嵌一次核心功能页
3. 文章底部"阅读全文/立即使用"   → 引导位，转化率高于正文
4. 关注自动回复带小程序入口      → 新粉第一时间给工具，而不是给文章
5. 公众号主页服务栏              → 展示小程序入口
6. 模板消息 / 订阅通知           → 服务类触达（不是营销类，滥用被封）
7. 搜一搜品牌账号页              → 公众号 + 小程序互相导流，同一关键词双结果位
8. 视频号绑定                    → 视频号主页可挂小程序，直播带货/预约场景必配

配套打法（内容 → 工具的转化闭环）：
├── 写"如何做 X"的教程文章，正文里嵌"用这个小程序 30 秒做完 X"
├── 一篇文章只推一个功能页，路径越短转化越高
└── 文章评论区置顶小程序码 —— 很多人懒得点卡片，扫更快
```

**【专题补写】** 公众号与小程序必须**同主体或已关联**才能互相绑定；关联操作在小程序后台"关联设置"里发起、公众号后台确认。个人主体小程序不能关联个人类型的订阅号做部分能力（如自定义菜单跳小程序的能力限制），配之前就确认清楚。

## 5. 分享裂变：小程序最主要的自有增长引擎

### 5.1 病毒系数机制设计

```
病毒系数 = 每个现有用户带来的新用户数

K < 1：增长靠外部渠道
K = 1：自增长平衡
K > 1：病毒式增长（每用户带来>1新用户）

机制1：邀请奖励
├── "邀请1位好友，双方各得7天Pro"
├── 关键：奖励对双方都有价值
└── 效果：通常提升K值0.1-0.3

机制2：内容水印
├── 免费版输出带品牌水印
├── 用户分享即传播
└── 效果：自然流量提升20-50%

机制3：协作刚需
├── 产品天然需要多人协作
├── Notion/Figma模式
└── 效果：每1用户带来2-5新用户

机制4：公开数据
├── 用户生成的内容/数据公开可见
├── 如：排行榜、公开页面
└── 效果：被动传播，K值提升0.2-0.5

机制5：社交证明
├── 展示使用人数、评价、案例
├── 降低新用户决策门槛
└── 效果：转化率提升30-100%
```

> 来源：`../super-individual/opc-growth-marketing.md:272-308`

**【专题补写】** 把五个机制映射到小程序，可行性和风险差别很大：

| 机制 | 小程序可行性 | 怎么做 | 风险 |
|---|---|---|---|
| 邀请奖励 | 高 | 分享卡片带邀请参数 → 被邀请人首次进入即绑定关系 | 奖励"必须双方都得"，强制分享/利诱分享会被判定违规 |
| 内容水印 | 高 | 生成海报图（用户成果 + 二维码）保存图片到相册 | 二维码必须是你自己的小程序码，不能引导关注公众号以外行为 |
| 协作刚需 | 中 | 拼单、共同编辑、组队报名——天然需要拉人进来 | 需服务端支持，开发量最大 |
| 公开数据 | 中 | 排行榜、公开主页可被搜一搜收录 | 展示他人信息需合规（见 06） |
| 社交证明 | 高 | 页面显示"已有 N 人使用" | 数字不能造假，虚假宣传是处罚项 |

```
小程序分享的技术前提（设计前先确认能实现）：
├── onShareAppMessage 必须在用户主动点击后才可引导，
│    不能在页面加载时自动弹分享
├── 分享出去的卡片只有"标题 + 图片 + 落地路径"三个可控制项
│    → 图片必须专门出（尺寸见 01 第 7.2 节），不要用默认截图
├── 落地路径要精确到具体内容页，不要统一回首页
└── 分享链路要带来源参数，才能算清 K 值（见第 9 节看板）
```

### 5.2 裂变活动 SOP（小程序版）

```
活动类型：限时免费升级
├── 规则：邀请3人注册，免费获得1个月Pro
├── 时间：7天限时
├── 渠道：产品内弹窗+邮件+社媒
├── 预期：K值从0.3提升至0.8
└── 成本：几乎为零（边际成本趋零）

活动执行：
Day 1：上线活动，全渠道推送
Day 2-3：监控数据，调整文案
Day 4：给已参与用户发提醒
Day 5：加大推送力度
Day 6：最后倒计时
Day 7：活动结束，公布成果，感谢参与者

效果评估：
├── 参与率：>10%用户参与
├── 邀请成功率：>30%被邀请者注册
├── K值提升：>0.3
├── 新增用户质量：与正常渠道相当
└── ROI：正（因为成本极低）
```

> 来源：`../super-individual/opc-growth-marketing.md:309-335`

**【专题补写】** 小程序版要改三处：**渠道换成"站内弹窗 + 公众号 + 社群"（没有邮件这一说）**、**"注册"换成"进入小程序并授权"**、**提醒换成订阅消息**。并且必须加一条前置检查：

```
小程序裂变活动前置检查清单：
├── □ 活动页是否要求用户先分享给好友/群才能领奖励？
│        → 这是"强制分享"，微信明令禁止，会被下架处理
├── □ 奖励是否诱导用户到公众号/其他平台？
│        → "分享后才能解锁全部功能"同样属违规
├── □ 是否有"抽现金""转发到 3 个群得 XX"这类明示话术？
│        → 高风险措辞，改写成"邀请好友一起用"
├── □ 活动是否有开始/结束时间，且实际按时间下线？
│        → 长期挂着的"限时"是投诉高发点
└── □ 服务端是否做了防刷（同设备/同 IP/同支付账号去重）？
         → 不设防的裂变活动，成本会被羊毛党吃掉

安全玩法（几乎不触发红线）：
├── 双方都得利的"邀请好友一起用"
├── 生成带二维码的成果海报，用户自愿保存图片
├── 组队/拼团（有真实交易标的）
├── 内容型分享（把结果分享出去本身就是产品价值）
└── 排行榜（公开数据 + 社交比较，不给物质奖励）
```

## 6. 付费投放

```
阶段1：测试期（$500/月，1-2月）
├── 目标：找到高转化关键词
├── 策略：精准长尾词，小预算测试
├── 指标：CAC < LTV的1/3
└── 产出：3-5个有效关键词

阶段2：放大期（$1000/月，2-4月）
├── 目标：规模化获客
├── 指标：ROAS > 3
└── 产出：稳定的获客渠道

阶段3：优化期（$2000+/月，4月+）
├── 目标：优化CAC和LTV
├── 策略：再营销、Lookalike、自动化
├── 指标：LTV/CAC > 3
└── 产出：可预测的获客机器

OPC广告黄金法则：
├── 先验证有机增长，再加付费
├── 小预算快速测试，数据说话
├── 关注LTV/CAC，不是点击量
├── 再营销比新客获取ROI高3-5倍
└── 暂停不盈利的广告，放大盈利的
```

> 来源：`../super-individual/opc-growth-marketing.md:225-254`（原文以 Google Ads 为例，阶段目标与法则通用）

```
└── 判断标准：如果自然分享带来的新用户占比 < 10%，
```

## 8. 留存：订阅消息与私域承接

### 8.1 订阅消息

**【专题补写】** 仓库只有零散提及，本节为补写。小程序没有推送权限，**唯一合规的主动触达手段是订阅消息**，这也是留存运营最大的天花板。

```
两种订阅：
├── 一次性订阅：用户授权一次 = 你只能发一条
│   └── 用途：预约提醒、结果通知、发货通知
└── 长期订阅：仅限特定类目（政务、医疗、交通等）
    └── OPC 大多申请不到，不要把它当常规手段设计留存

三个必须知道的操作事实：
1. 授权弹窗只能由用户主动点击行为触发（按钮绑定），
   不能在进入页面时自动弹
2. 用户可以在弹窗里勾选"总是保持以上选择"，之后不再询问
   → 这是你唯一能把订阅率做高的机会，
     所以第一次申请的场景要挑"用户正想要通知"的时刻
3. 一次授权只够发一条，发完即失效
   → 高频提醒类产品必须在每次核心动作后重新收集授权

最佳触发时机（按转化质量排序）：
├── 下单/报名/预约成功页（用户明确想知道后续）
├── 任务完成需要等待时（"好了叫你"）
├── 连续打卡/进度类节点
└── 不要在首页冷启动时就弹，授权率极低且招投诉

合规底线：订阅消息是服务通知，不是营销推送。
用服务通知发促销，会被限制能力（详见 06）。
```

> 政策快照｜截至 2026 年 10 月。平台规则会调整，发布前请核对官方文档，以官方为准。

### 8.2 私域承接

```
公域引流 → 私域沉淀 → 信任建立 → 商业变现 → 口碑传播

私域阵地（沉淀）：
├── 微信公众号（内容阵地）
├── 微信个人号/企业微信（1对1沟通）
├── 微信社群（互动交流）
├── 知识星球（付费社群）
└── 邮件订阅列表（Newsletter）

信任建立（培育）：
├── 持续输出高质量内容
├── 及时回复用户问题
├── 提供超出预期的价值
├── 分享真实的个人经历
└── 建立专业可信的形象
```

同一个链路模型还给了后两级，照录在这里——因为小程序的裂变动作全部落在这两级上：

```
商业变现（转化）：
├── 课程/专栏推广
├── 咨询服务转化
├── 社群付费升级
├── 企业合作对接

├── 老用户推荐新用户
├── 案例分享和见证
├── 社群口碑传播
└── 内容二次传播
```

> 来源：`../super-individual/personal-ip-guide.md:396-407`

**【专题补写】** "商业变现"那一栏的五种转化动作属于产品形态与定价，本篇不展开，见 [05-monetization.md](./05-monetization.md)。这里只把"口碑传播"四条翻译成小程序里的具体动作——这四条在原文是通用私域语言，落到小程序各有唯一对应的实现：

```
老用户推荐新用户 → 第 5 节的邀请机制，K 值就从这条链路算出来
案例分享和见证   → 结果海报：把用户用完后得到的成果做成可保存图片，
                   图上带小程序码（用户保存图片就等于替你带走了入口）
社群口碑传播     → 群内固定"成果展示"话题位，由用户自己发，
                   官方账号下场夸自己的产品，效果等同于刷屏

                   + 抖音挂载与直播（第 11 节）
```

**【专题补写】** 这四条里前两条最容易踩线。"分享给好友才能解锁功能/才能领取"属于强制分享，是诱导分享红线里处罚最明确的一类；差别在于**奖励是给"分享这个动作"还是给"用完后产生的成果"**——前者违规，后者合规。写裂变文案前先读 [06-legal.md](./06-legal.md)。

**【专题补写】** 对小程序来说，私域不是"额外的渠道"，而是**小程序留存的备份链路**——因为用户下次会不会再点开你的小程序，你完全控制不了；但他在不在你的群/公众号关注列表里，你控制得了。

```
小程序 → 私域的四个导流位：
├── 完成核心任务后的"遇到问题？加交流群"入口（转化率最高）
├── 我的页面 → 客服（企微/个人号承接）
├── 结果海报上的二维码（用户保存图片即带走入口）

├── 群内每周一次"工具用法/新特性"，附具体功能页小程序码
├── 公众号推文内嵌卡片（见第 3 节）
└── 不要每天推 —— 高频推送杀死的不是打开率，是群

社群节奏（可直接沿用）：
免费社群：规模 200-500 人
├── 每日：行业资讯/工具推荐（5分钟）
├── 每周：话题讨论/经验分享（30分钟）
└── 每月：嘉宾分享/线上活动（1小时）
```

```
├── 客服工单量
├── 社媒互动数
├── 内容发布数
└── 邮件打开率
```

> 来源：`../super-individual/opc-growth-marketing.md:341-368`

**【专题补写】** 小程序版把两行换掉，再加两行小程序特有的：

```
流量层改造：
├── "流量来源分布" → 按 scene 场景值分布
│   （分享/搜一搜/扫码/公众号菜单/广告各占多少，字段映射见 03）
└── "跳出率" → "进入后未完成任一核心行为的比例"

运营层改造：
├── "邮件打开率" → "订阅消息发送数 / 授权剩余条数"
│   （授权余量是资产，用完要补，不然触达链路会断）
└── 新增："分享率" = 主动点击分享的用户 / 当日活跃
└── 新增："回流率" = 通过分享卡片进入的新访客 / 分享次数
    这两个数直接决定 K 值，是小程序最该盯的比值

K 值怎么算（不要靠平台数据猜）：
├── 分享卡片带来的、且带 unique-id 来源参数的新用户数
├── 除以 当日发起分享的用户数
└── 埋点实现见 03 的"三个公共字段"
```

### 9.2 A/B 测试

```
测试什么：
├── 着陆页标题（影响最大）
├── 定价页面（直接影响收入）
├── CTA按钮文案
├── 注册流程步骤
└── 推送通知时间

怎么做（无需复杂工具）：
├── 方法2：简单轮换（50/50流量，手动切换）
├── 方法3：按时间对比（本周 vs 上周）
└── 方法4：按渠道对比（A版本给SEO流量，B版本给社交流量）

最小可行样本：
├── 转化率测试：每个版本>100转化
├── 点击率测试：每个版本>1000点击
├── 收入测试：每个版本>30天数据
└── 不要过早下结论，统计显著性>95%
```

> 来源：`../super-individual/opc-growth-marketing.md:383-401`

**【专题补写】** 小程序做 A/B 的现实约束：不能靠前端随机分流以外的任何平台能力，所以**用服务端下发配置**做分流（和灰度机制是同一套开关，实现见 [03-operations.md](./03-operations.md)）。方法 4 在小程序里最实用：同一版本，把"搜一搜进来的用户"和"分享卡片进来的用户"分别展示不同首屏，用 scene 字段天然分组，零开发成本。

```
小程序优先测这四件事（按对结果的影响排序）：
1. 首屏 CTA 的文案与位置       → 直接影响激活率
2. 分享卡片的标题与图片         → 影响 K 值，一次改动全域生效
3. 授权弹窗出现的时机           → 影响授权率，且不影响功能，风险最低
4. 空状态的引导按钮             → 新用户第一眼看到的往往就是它
```

## 10. 增长瓶颈诊断

```
| 瓶颈 | 症状 | 根因 | 解法 |
|------|------|------|------|
| **无流量** | 日访客<50 | SEO未起量+无分发 | 内容矩阵+社区渗透 |
| **有流量无注册** | 访客>500，注册<10 | 价值主张不清 | 优化Landing Page |
| **有注册无付费** | 注册>100，付费<3 | 产品价值未验证 | 免费增值+使用引导 |
| **有付费无留存** | 首月付费>10，次月<3 | 产品未解决痛点 | 用户访谈+产品迭代 |
| **增长停滞** | 连续3月增长<5% | 渠道饱和或产品天花板 | 新渠道+产品扩展 |
```

> 来源：`../super-individual/opc-growth-marketing.md:416-422`

**【专题补写】** 换成小程序诊断表（"注册"改"授权/完成核心行为"，并补上小程序特有的两类瓶颈）：

| 瓶颈 | 症状 | 小程序特有风险 | 解法 |
|---|---|---|---|
| 无流量 | 日访问 < 50 | 免费入口一个都没配 | 按第 1-4 节逐条盘点，先做搜一搜和公众号 |
| 有访问无激活 | 访问多但完成核心行为 < 20% | 落地页与入口场景不符（分享深链回首页） | 分享路径精确到内容页；空状态给一键示例 |
| 有激活无回访 | 次日留存 < 15% | 产品是"用完即走"型 | 承认现实，改做交易/订阅而非日活；或加进度/榜单机制 |
| 有分享无回流 | 分享率高、回流极低 | 卡片标题与图片没有点击冲动 | 测第 9.2 节第 2 项 |
| 有回流被举报 | 增长不错但出现投诉 | 玩法触碰诱导分享红线 | 立刻下线活动，对照 06 第 9.2 节红线清单整改 |
| 有付费无留存 | 首月付费多、次月掉 | 价值未持续 | 用户访谈 + 双周迭代（节奏见 01） |

```
# 3. 引导用户使用
# 4. 数据分析优化

```

> 来源：`../super-individual/app-publishing-guide/mini-program/douyin.md:321-344`

**【专题补写】** 抖音小程序的流量完全绑在内容产能上，OPC 一个人最容易死在"发三周没爆就放弃"。给一个可执行的周节奏：

```
每周产能（一个人可承受的上限，超过就会断更）：
├── 3 条短视频（同一条核心演示，换 3 个开头钩子）
├── 1 条评论区/私信集中回复（挂载类问题固定答疑）
└── 1 次数据复盘（哪条带来了小程序访问，只保留成功钩子）

内容结构（工具类小程序通用套路）：
├── 0-3 秒：抛出具体痛点的画面或一句话，不要 logo 不要片头
├── 3-15 秒：现场用小程序做一遍，让工具本身当主角
├── 15-25 秒：给一个"结果对比"（做前 vs 做后）
└── 结尾：口播一句"评论区第一个字/点下方直接用"，
    引导语必须指向挂载入口，不然看完就划走

挂载与账号：
├── 抖音号先与小程序完成绑定，主页才出现入口
├── 同一素材不同开头 → 是最便宜的 A/B，
│   比在小程序里做分流快得多
└── 爆款出现时立刻补 3 条同主题 —— 平台给的是波峰，不抓就过

投放（可选）：
└── 只在已经自然跑出小程序访问的素材上追投，
   冷启动期不要开投放（见第 6 节黄金法则）
```

## 13. 失败模式与基准数据：运营该盯哪几条

**【专题补写】** 本节不加新的方法论，只做一件此前没做过的事：把仓库里那份 OPC 失败案例与社群调研数据（`../super-individual/opc-case-studies.md` 第 4 节）按"能否改变本篇动作"筛一遍。四类失败模式里只有 B 类是纯运营问题，其余三类各有归属，见本节末尾的对照。

原文对平台依赖型的记录，这一条对小程序最直接：

```
**失败模式B：平台依赖型**

典型案例：
├── 背景：自媒体运营者
├── 模式：单一平台（如抖音）带货
├── 问题：100%收入来自一个平台
├── 结果：平台政策变化，收入归零
├── 原因：没有私域沉淀，没有多渠道

教训：
├── 任何单一平台收入不超过总收入的50%
├── 必须建立私域（邮件列表、社群）
├── 平台是渠道，不是资产
└── 尽早建设独立站和品牌
```

> 来源：`../super-individual/opc-case-studies.md:307-322`

**【专题补写】** 这类失败在小程序语境下比在 App 语境下更严重：**App 的入口至少还能靠商店搜索和品牌词争取，小程序的入口本身就不属于你**（第 1 节整节讲的都是平台分配）。而且原文那条"尽早建设独立站"在小程序里不能照抄——独立站与小程序是两个体系，小程序的对应解法是第 8.2 节的私域位。可执行的自检：

```
渠道集中度自检（每月一次，数据口径见 03）：
├── 新增侧：按 scene 场景值算占比，任何单一入口 > 50% 标红
├── 收入侧：广告 / 内购 / 服务 各占多少（费率与到手额见 05）
└── 两侧都算完，再决定第 6 节要不要继续加预算
    （原文"先验证有机增长再加付费"的前提，就是这里的集中度已经散开）

典型的一条假好消息：新增 80% 来自搜一搜
├── 看着好：免费、意图明确、转化率通常是各入口里最高的
├── 实质：平台改一次排序就归零，与 B 类同一种死法
└── 处置不是放弃搜一搜，而是用同一批内容把私域位填满
    —— 搜一搜带来的用户里，能沉进群/公众号的那部分才是你的资产
```

另两类失败模式与运营动作无关，但会直接终结项目，原文教训照录：

```
C AI 工具依赖型：
├── AI是杠杆，不是产品本身
├── 必须解决真实用户的真实痛点
├── 构建数据飞轮或网络效应壁垒
└── 持续创新，而不是一次性套壳

D 现金流断裂型：
├── 全职转型前，副业收入需连续6月超工资
├── 保持至少12个月生活费的储备
├── 先验证商业模式，再all in
└── 考虑渐进式转型，而非断崖式
```

> 来源：`../super-individual/opc-case-studies.md:324,334-338,341,350-355`（每型下的"典型案例"块 `:327-332,344-349` 未转录，本节只取教训四条；A 型的完整原文转录在 [01-design.md](./01-design.md) 第 1 节）

**【专题补写】** D 那四条是转型决策而非运营决策，但它是第 6 节投放预算的现实上限来源：**在月度到手利润能覆盖生活费之前，投放预算必须停在"整月亏掉也不影响生活"的量级**。A 类（技术自恋、发布前未验证需求）归 [01-design.md](./01-design.md) 第 1 节展开，本节不重复；C 类里"壁垒"那半句同样是产品问题，归 01。

### 13.1 SoloNest 社群调研数据

```
2000+ OPC创业者样本分析：

成功率分布：
├── 稳定盈利（月入>当地平均工资）：20%
├── 偶尔盈利（有不稳定收入）：30%
├── 收支平衡（收入覆盖成本）：15%
├── 持续亏损（投入>产出）：20%
├── 已放弃（停止运营）：15%

成功者的共同特征：
├── 有明确的细分领域定位：85%
├── 坚持公开构建（build in public）：70%
├── 拥有私域流量池：65%
├── 产品矩阵（非单一产品）：60%
├── 及时拥抱AI工具：75%

失败者的共同特征：
├── 产品发布前没有验证需求：80%
├── 过度追求完美，延迟发布：65%
├── 单打独斗，不加入社群：70%
├── 没有持续迭代，发布后放任：60%
├── 贸然全职，现金流断裂：45%
```

> 来源：`../super-individual/opc-case-studies.md:361-384`（数据来源说明见原文 `:359`：SoloNest 社群主理人 2026 年公开分享）

**【专题补写】** 先讲口径再讲用法。样本是**自选择进入 OPC 社群的人群**，不是随机抽样，也不是按平台或品类分层的，所以"稳定盈利 20%"不能当作做小程序的成功概率使用——它既可能高估（进社群的人本来更主动）也可能低估（社群外大量默默赚钱的人没被计入）。**可用的是成功者与失败者特征之间的相对差距**，它回答"时间该投在哪"，不回答"我能不能成"。

按能否改变本篇动作筛这几条：

| 特征（原文占比） | 本篇对应的动作 | 位置 |
|---|---|---|
| 拥有私域流量池（成功 65%） | 私域不是可选项，按最小栈搭起来 | 8.2 |
| 坚持公开构建（成功 70%） | 冷启动 Step 3 的内容占位就是它的国内版 | 7 |
| 单打独斗、不加入社群（失败 70%） | 至少进 2-3 个同类小程序的群做信息交换 | 7 Step 2 |
| 没有持续迭代，发布后放任（失败 60%） | 上线是运营的起点，按双周节奏迭代 | 01 第 8 节 |
| 发布前没有验证需求（失败 80%） | 需求验证清单 | 01 第 1 节 |
| 贸然全职，现金流断裂（失败 45%） | 投放预算与转型节奏的上限 | 本节、05 第 7 节 |

**【专题补写】** 这批数字有三处常被误用，点名一次：

```
1. "多平台同开能对冲" —— 成功特征里那条是"产品矩阵（非单一产品）"，
   指的是多个产品，不是同一产品的多个平台。一个人三平台同开的真实结果
   通常是三个都做不深（三平台运营投入差异见第 1 节的对比表）
2. "有私域"≠"有转化" —— 65% 统计的是"拥有私域流量池"这个状态，
   私域变现要过 05 的载体抽成与到手额换算。
   把私域人数直接当收入预期，是这批数据最容易踩的一处误读
3. 成功特征不可加总 —— 85%／70%／65%／60%／75% 是各特征的独立占比，
   不是"同时满足"的比例，推不出"做到五条就有八成成功率"
```

## 需你复核的事实

本篇补写内容集中在这张表。原文照搬的条目（入口清单、私域链路模型、投放阶段法则、失败模式与调研数据）不在此列；但**凡本篇把原文的数字或结论用在另一个对象上**（如把"单一平台收入不超 50%"迁移到入口占比）也在表里登记，因为数字可信、换算是本篇的判断。

| 项 | 本文写法 | 复核入口 |
|---|---|---|
| 搜一搜页面路径收录入口 | 写作"后台可提交页面供索引" | 小程序后台 → 搜一搜相关设置 |
| 附近的小程序地点数量上限 | 写作"有限，优先核心门店"，未给数字 | 小程序后台 → 附近的小程序 |
| 公众号关联需同主体/需确认 | 按既有规则表述 | 小程序后台关联设置 + 公众号后台 |
| 长期订阅消息仅限特定类目 | 写作"OPC 大多申请不到" | 微信订阅消息开放类目清单 |
| 一次订阅只能发一条 | 写作平台机制事实 | 微信订阅消息官方文档 |
