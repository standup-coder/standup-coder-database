# Git 卫生

只提交该提交的东西，用说清"为什么"的方式提交。

## 提交前检查（每项都要实际执行）

1. `git status`：确认没有意外文件。构建产物、日志、`.env`、编辑器配置一律不入库（先确认 .gitignore 覆盖，而不是直接 add）。
2. `git diff --stat`：改动分布与本次意图一致。出现与任务无关的文件，单独指出并询问是否纳入。
3. `git diff` 逐文件扫一遍：无残留调试输出（console.log / print）、无注释掉的代码、无硬编码密钥或本地路径。
4. 敏感信息扫描：密钥、token、内网地址、真实个人数据。发现即停止提交并报告。

## 提交规则

- **单一意图**：功能、修复、重构、格式化不混在一个提交里。发现混了就建议拆分（`git add -p`）。
- **提交信息**：说明为什么与影响，不只是罗列文件。格式：一行摘要（≤72 字符）+ 空行 + 必要时的动机/影响说明。
- **不提交半成品**：提交后测试必须全绿；做不到就说明原因，而不是降低检查标准。
- **绝不**：force push 共享分支、rebase 用户未授权的分支、绕过 hooks（`--no-verify`）除非用户明确要求。

## 分支

- 从最新主干切出，命名反映意图（`feat/xxx`、`fix/xxx`、`refactor/xxx`）。
- 与用户确认分支策略后再操作远端。

## 提交授权

默认不主动 commit / push。用户要求提交时，先展示将提交的内容（status + diff 概要）再执行。
