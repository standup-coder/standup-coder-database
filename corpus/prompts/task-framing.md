# 提示词模板：把模糊需求变成清晰任务

## 何时用

当你的需求还是一句模糊的话（"帮我做个登录""把首页优化一下"），直接丢给 agent 大概率得到一个方向跑偏的实现。先用这个模板把需求自己想清楚，再交给 agent。

## 模板

```text
目标：<一句话说清做成什么样算完成>
背景：<项目/模块是什么，相关文件或入口在哪>
约束：
- 技术栈：<现有技术栈，别引入新框架>
- 范围：<只改哪些部分，明确不要动什么>
- 兼容：<需要保持的行为/接口>
验收标准：
1. <可观察的具体结果，如"npm test 全绿">
2. <如"未登录访问 /admin 跳转到 /login">
3. <如"构建无类型错误">
非目标：<明确列出这次不做的事>
```

## 变量说明

| 变量 | 说明 |
| --- | --- |
| 目标 | 用"完成后的样子"描述，不写实现步骤 |
| 约束·范围 | 最重要的一个变量。写清"不要动什么"比写"要做什么"更能防止 agent 跑偏 |
| 验收标准 | 必须是 agent 能自查的客观判据（测试通过 / 页面行为 / 构建结果），不写"体验好一点" |

## 示例（改写前 → 改写后）

- 模糊："给项目加个暗色模式。"
- 清晰："目标：站内切换暗色模式且记住选择。约束：只改样式层，用 CSS 变量，不加依赖；不动路由与数据逻辑。验收：1) 顶栏切换按钮即时生效；2) 刷新后保持上次选择；3) build 通过。非目标：不做跟随系统设置。"
