# 前线部署工程师(FDE)职位描述(JD)

## 岗位基本信息
- **岗位名称**：前线部署工程师(Forward Deployed Engineer / FDE / 客户现场AI工程师)
- **岗位定位**：客户面向技术层 - 深入客户现场的全栈AI交付工程
- **工作性质**：全职(高频客户现场驻场/出差)
- **工作地点**：北京/上海/深圳/杭州(+客户现场)
- **招聘人数**：若干
- **薪资范围**：国内 20K-80K/月(初级20-35K，中级35-55K，高级/负责人55-80K+)；国际前沿实验室 base $16万-$44万/年、总包 $35万-$128万(详见真实JD章节)
- **团队规模**：FDE团队10-100人，2-4人小组制作战

> **术语辨析**：FDE业界通行含义为Forward Deployed Engineer(前线部署工程师)，由Palantir开创并因OpenAI/Anthropic大规模招聘而成为2025-2026年最热门的AI岗位之一；部分国内招聘中亦写作Field Deployment/Development Engineer(现场部署工程师)，岗位内核一致——本文按Forward Deployed Engineer口径沉淀。

## 公司与行业背景

### 行业背景
FDE是"产品公司做交付"的独特解法：由具备完整工程能力的工程师深入客户现场，在数周内将平台/模型能力落成客户生产系统，同时把现场共性需求反哺产品化。Palantir以FDE模式支撑了其政企业务的高速增长；OpenAI于2025年组建FDE团队帮助企业客户落地GPT系列能力，Anthropic、Mistral、Cohere、xAI等国际公司迅速跟进；国内字节/火山引擎(豆包)、阿里云、腾讯云智、智谱AI等有企业客户基础的平台型厂商已明确设立FDE/前沿部署工程师岗，月之暗面/MiniMax/百川等正转向B端但多以"解决方案架构师/交付工程师"命名(详见下文真实JD章节与趋势参考)。FDE区别于传统交付工程师的关键：**以产品工程师标准写代码、以创业者姿态对客户业务结果负责**。有"全栈工程 + LLM应用 + 客户现场抗压"复合能力者极度稀缺，顶级公司FDE薪酬对标资深研发甚至更高(国际前沿实验室FDE总包中位$38.5万-$100万+，国内头部年包50-120万)。

## 岗位职责

### 客户现场AI系统交付
- 深入客户现场理解业务流程，将模糊需求转化为可交付的AI系统设计
- 端到端开发客户侧应用(数据接入/RAG管道/Agent编排/前端交互)
- 完成模型选型与效果调优(Prompt工程/微调评估/成本-效果权衡)
- 在客户环境(含私有化/离线环境)完成部署、联调与性能优化
- 以周为单位迭代交付，快速展示价值并赢得客户信任

### 数据工程与系统集成
- 打通客户内部系统(ERP/CRM/工单/知识库)与AI平台的数据链路
- 设计数据清洗、脱敏与权限方案(满足客户安全合规要求)
- 开发定制化连接器与API集成层
- 建设客户侧评测集与效果度量看板

### 产品反哺与方案沉淀
- 识别客户现场的共性需求，推动产品团队将定制能力产品化
- 沉淀行业模板与可复用交付资产(方案库/组件库/评测集)
- 输出标杆案例与最佳实践文档
- 参与产品新特性的现场验证与反馈闭环

### 客户关系与商业支撑
- 与客户技术与业务负责人建立信任关系，管理交付预期
- 支撑POC攻坚与商务谈判中的技术论证
- 识别客户增购机会并联动销售推进
- 主导交付项目的里程碑汇报与验收

## 任职要求

### 必备技能

**全栈工程能力**：
- 精通Python，熟悉TypeScript/React者优先；能独立完成端到端应用开发
- 熟悉后端服务开发(FastAPI/gRPC)与数据库设计(SQL/NoSQL)
- 具备Docker/K8s部署能力，能应对客户多样化基础设施
- 强Debug能力(在陌生环境快速定位跨系统问题)

**LLM应用能力**：
- 熟练掌握RAG系统建设(切分/检索/Rerank/评测全链路)
- 熟悉Agent开发范式(Function Calling/工具编排/MCP协议)
- 掌握Prompt工程与效果评测方法论
- 理解微调适用边界(何时SFT/何时RAG/何时换模型)

**现场作战能力**：
- 极强的需求理解与抽象能力(从业务语言到系统设计)
- 出色的沟通与预期管理能力(客户高层到一线用户)
- 高度自驱与抗压能力(现场资源有限、时间紧迫)
- 快速学习能力(每个项目都是新行业新系统)

### 经验要求
- **学历要求**：本科及以上学历，计算机/AI/数学/物理等相关专业优先(国际前沿实验室普遍接受同等经验替代学位；Palantir接受1+年经验入门)
- **工作经验**(各公司门槛差异显著，详见真实JD章节)：
  - 初级岗位：1-4年(Palantir FDSE门槛最低1+年；Scale AI/腾讯云智 2-5年)，全栈开发背景+LLM应用项目经验
  - 中级岗位：4-7年(OpenAI/Anthropic/xAI/Databricks要求4-7+年)，独立交付过完整客户项目或创业经历
  - 高级/负责人岗位：7年以上(智谱FDE负责人、阿里云高级)，主导过行业级AI方案交付或FDE团队建设
- **项目经验**：有从0到1交付生产级系统的完整经历(个人项目/创业/交付均可)——这是所有FDE岗位的共同硬性偏好

### 加分技能
- 有创业经历或独立开发者背景(FDE最看重的owner意识)
- 有私有化/离线环境部署经验(国产化/信创环境优先)
- 有咨询公司或解决方案架构师背景(结构化问题拆解)
- 有垂直行业Know-How(金融/制造/政务/医疗)
- 英语工作能力(国际AI公司硬性要求)
- 有运维/SRE背景(客户环境疑难杂症的降维打击能力)

## FDE与相邻岗位区别

FDE常与解决方案架构师(SA)、技术客户经理(TAM)、开发者关系(DevRel)、专业服务(PS)等客户面向技术岗混淆。核心区别如下：

| 维度 | FDE | 解决方案架构师(SA) | 技术客户经理(TAM) | 开发者关系(DevRel) | 专业服务(PS) |
|------|-----|--------------------|--------------------|---------------------|--------------|
| **核心动作** | 写代码交付生产系统 | 售前方案设计与POC | 售后护航与用量增长 | 布道/内容/社区 | 按SOW交付项目 |
| **写代码占比** | 高(25-50%工时) | 低(以架构图/文档为主) | 极低(以协调为主) | 中(示例代码/SDK) | 中(按合同范围) |
| **对谁负责** | 客户业务结果+产品反馈 | 成交转化 | 客户健康度/续费 | 开发者生态 | 项目验收 |
| **出差/驻场** | 高(25-50%+驻场) | 中(售前阶段) | 低-中 | 低 | 高(按项目) |
| **产品反哺** | 核心职责(双向闭环) | 次要 | 反馈故障/需求 | 反馈社区需求 | 弱 |
| **典型薪资(国内)** | 35-80K/月 | 30-65K/月 | 25-55K/月 | 30-60K/月 | 25-50K/月 |
| **画像关键词** | "会写代码的创业者" | "懂技术的售前" | "客户的技术管家" | "开发者代言人" | "按合同交付的工程师" |

> **一句话区分**：FDE = SA的方案能力 + 全栈工程师的写代码能力 + TAM的客户关系深度 + 产品经理的反哺意识。它是这四个角色的交集，也是其稀缺性与高薪的根源。参见 [technical-account-manager.md](./technical-account-manager.md)、[ai-solution-architect.md](./ai-solution-architect.md)、[developer-relations.md](./developer-relations.md) 对照。

## 一、国际AI公司真实JD

### 案例1：OpenAI - Forward Deployed Engineer (FDE)
**公司规模**：约2000+人，估值$5000亿+，私有
**岗位别名**：FDE / Forward Deployed Engineer, Gov / Forward Deployed Software Engineer(FDSWE) / Technical Deployment Lead, FDE
**薪资范围**：中级 base $16万-$28万；高级 base $22万-$30万；Staff base $28万+。总包：中级 $35万-$45万、高级 $45万-$55万、Staff $55万+；对标L5-L6资深SWE总包可达 $70万-$128万。股权占总包60%-70%
**工作地点**：旧金山 / 纽约(主枢纽，约占35%岗位) / 西雅图 / 华盛顿DC；国际：伦敦/慕尼黑/巴黎/新加坡/东京/悉尼/都柏林。混合办公(每周3天到岗)
**出差比例**：最高50%，驻场嵌入客户工程团队；纯远程不可行

**岗位职责**(据官方JD与Paraform指南核实)：
- 主导前沿模型在战略企业客户生产环境的复杂端到端部署
- 负责发现、技术范围界定、系统设计、构建与上线全流程，直接对接客户工程与业务团队
- 构建交付客户价值并反哺OpenAI模型能力的全栈系统
- 部署、微调并集成OpenAI模型至客户生产系统
- 为战略客户实现护栏(Guardrails)、评测(Evals)与重试逻辑
- 作为客户账户的首要技术联系人(架构问题/生产Debug/模型配置调优)
- 将真实部署摩擦、边界用例与功能缺口反哺内部产品与研究团队

**任职要求**：
- 至少5年工程或技术部署经验，有客户面向背景
- 证明过的问题拆解能力(将模糊企业问题转化为可界定的工作流)
- 能向CTO讲清架构权衡，同时向非技术出资方翻译时间线

**技术栈**：Python + JavaScript全栈；RAG管道、评测框架、Agent工作流

**特色**：现代FDE打法的起源(借鉴Palantir)。以"拆解面试(decomposition interview)"著称——候选人拿到模糊的大规模问题，必须先澄清范围再写伪代码。双向反馈闭环：FDE既对结果负责，也喂给内部路线图
**数据来源**：openai.com/careers、Paraform OpenAI FDE指南(2026.06)、Perspective.ai 2026 FDE薪酬报告

### 案例2：Anthropic - Forward Deployed Engineer, Applied AI
**公司规模**：约1000+人，私有(Claude)
**岗位别名**：Forward Deployed Engineer, Applied AI(规范名称；注意不存在"Forward Deployed Solutions Engineer"这一变体)。管理线：Manager, FDE / Head of FDE

**工作地点**：旧金山 / 纽约 / 西雅图(混合)；部分远程；波士顿亦有岗位
**出差比例**：25%-50%到客户现场

**岗位职责**(据Menlo Ventures/General Catalyst联合发布JD原文)：
- 在客户系统内基于Claude模型构建满足客户要求的生产级应用
- 为客户交付技术制品：MCP servers、sub-agents、agent skills，用于实时生产环境
- 为企业客户提供"白手套部署支持"
- 识别并固化可复用部署模式，反馈内部产品与工程团队
- 持续跟进LLM能力、实现模式与AI产品开发栈
- 培养长期客户关系，主动发掘新部署机会

## 常见误区与避坑

### 误区1："FDE就是高级交付工程师/外包"
**事实**：FDE以产品工程师标准招人、写代码、定架构，薪资对标资深研发甚至更高(OpenAI/Anthropic FDE总包$35万-$100万+)。传统交付工程师按SOW执行，FDE对客户业务结果负责并有产品反哺话语权。判断一个"FDE"岗位是否名副其实：**看它要不要你现场写代码、要不要你对产品路线图有输入**。

### 误区2："FDE不需要很强的技术能力，主要是沟通"
**事实**：国际前沿实验室FDE面试含**decomposition interview**(模糊问题拆解+现场编码)、Take-home端到端项目(48小时-7天)、现场编程(工具调用循环等)。技术不硬连Take-home都过不了。沟通是必要不充分条件。

### 误区3："国内没有真正的FDE岗位"
**事实**：字节/火山引擎(豆包FDE)、阿里云(前沿部署工程师)、腾讯云智(AI前线部署工程师)均已明确设立FDE命名岗(详见真实JD案例19-21)。区别在于国内部分公司仍用"解决方案架构师/交付工程师/PDSA"命名但内核一致。

### 误区4："FDE是青春饭，做几年就废了"
**事实**：FDE的职业出口极广——转产品负责人(最懂客户)、转解决方案架构师首席、转创业(FDE最接近真实付费需求)、转甲方AI团队负责人。Palantir FDE出身的多位已成为行业方案首席架构师或创业CEO。

### 误区5："不想出差就别做FDE"
**事实**：出差比例因公司差异大——Palantir 25%、Anthropic 25-50%、OpenAI最高50%、Harvey全职嵌入6-9个月；国内岗多为项目制驻场(非永久出差)。面试时务必问清出差预期与驻场补贴机制。

### 误区6："国际公司FDE必须在美国"
**事实**：OpenAI在伦敦/慕尼黑/巴黎/新加坡/东京/悉尼/都柏林均有FDE岗；Mistral在阿姆斯特丹/伦敦/巴黎；xAI在纽约/帕洛阿尔托。但国际公司FDE普遍要求**英语工作能力**。

## 面试准备建议

### 高频面试题
1. **需求拆解**：客户说"想用大模型提升客服效率"，给你30分钟现场沟通，你会问哪些问题？如何在一周内给出可演示的方案？
2. **技术选型**：客户知识库问答效果差，如何系统性定位是切分、检索、Prompt还是模型问题？各环节的评测方法是什么？
3. **私有化交付**：客户环境离线且GPU型号受限(含国产卡)，你的部署与降级方案如何设计？
4. **现场危机**：演示前夜发现核心链路效果退化，明早客户CEO到场，你怎么办？
5. **产品反哺**：连续三个客户都要求同一个定制功能，你如何推动产品化？推动失败怎么办？
6. **边界管理**：客户不断加需求且拒绝加预算，如何在保住关系的同时守住交付边界？

### 系统设计/方案题
- 为一家银行设计合规审查智能体系统(数据不出域/审计留痕/人机协作)
- 设计一套可复制的行业知识库交付方法论(从数据盘点到验收标准)
- 设计客户侧LLM应用的评测与监控体系(效果/成本/安全三维)
- 为制造业客户设计设备故障问答系统(多模态文档/表格/图纸处理)

### 实操考察
- Take-home项目：48小时内基于给定数据构建可演示的RAG应用
- 现场编程：实现一个带错误处理的工具调用循环
- 模拟客户沟通：面试官扮演难缠客户，考察需求澄清与预期管理
- 方案白板：现场设计一个行业场景的端到端架构并答辩

### 面试流程
1. **HR初筛**(30分钟)：重点确认出差意愿与抗压预期
2. **技术一面**(1-1.5小时)：全栈工程 + LLM应用深度
3. **Take-home/实操**(2-7天)：交付一个小型端到端项目
4. **场景二面**(1.5小时)：项目答辩 + 模拟客户沟通
5. **交叉面**(1小时)：产品/销售负责人考察协作与商业感
6. **总监面**(1小时)：owner意识与职业动机
