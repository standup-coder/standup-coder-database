# 仓库探索

在本仓库上做任何修改前，按此流程建立经过验证的理解。原则：**每个结论都有文件证据，不输出未核对的推断。**

## 步骤

1. **读入口层**：README、包描述文件（package.json / pyproject.toml 等）、目录顶层结构、`git log --oneline -20`。先说清：这是什么项目、用什么栈、最近在改什么。
2. **画依赖地图**：从入口文件追踪 → 主要模块及职责 → 依赖方向 → 配置加载方式。每个模块必须给出至少一个代表文件的真实路径。
3. **自我核对**：输出地图前，逐个打开你引用的文件确认内容与描述一致。发现描述与代码不符时，以代码为准并显式标注修正。
4. **定位目标区域**（若有具体任务）：从入口追踪到目标功能的调用链，列出涉及文件、各处职责、测试覆盖情况。
5. **报告测试基线**：运行测试套件，区分"本来就红的测试"与"本次需要关注的测试"。

## 输出格式

- 结构地图 ≤ 60 行，每个断言后附 `文件路径`。
- 涉及不确定的推断时，标注 `[未核对]`，绝不冒充事实。

## 禁止

- 在探索阶段修改任何文件（跑项目所需的最小环境修复除外，须单独说明）。
- 输出未打开过的文件的内容摘要。
- 用"通常这类项目会……"替代对该仓库的实际检查。
