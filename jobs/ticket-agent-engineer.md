# 工单智能体工程师职位描述(JD)

## 岗位基本信息
- **岗位名称**：工单智能体工程师(Ticket Agent Engineer / 智能工单系统研发工程师)
- **岗位定位**：运维智能化层 - 技术服务与工单处理智能化
- **工作性质**：全职
- **工作地点**：杭州/北京/深圳/上海/成都
- **招聘人数**：若干
- **薪资范围**：30K-70K/月
- **团队规模**：技术服务智能化团队10-60人，工单智能体小组5-12人

## 公司与行业背景

### 行业背景
云厂商与大型软件企业每年处理百万级技术工单，传统模式依赖人工分诊、专家排班与逐单排查，成本高且响应时效受限。大模型使工单处理链路全面重构：智能体可完成工单理解与分类、信息补全追问、基于知识库与历史案例的预诊断、解决方案推荐、直至部分场景的自动闭环，人工专家聚焦复杂疑难单。工单数据同时是运维语料的富矿——"工单对话+排查过程+解决方案"的闭环记录是训练与评测垂域智能体的核心资产，因此该岗位常与语料工程职责深度绑定，是"技术服务(GTS)体系"向"AI驱动服务"转型的关键角色。

## 岗位职责

### 工单智能体研发
- 负责工单智能体的架构设计与研发(理解-分诊-诊断-解答-闭环)
- 开发工单智能分类、优先级研判与自动流转能力
- 建设信息补全追问机制(引导用户提供日志/集群ID/复现步骤)
- 实现基于RAG的解决方案推荐与相似工单匹配
- 开发工单摘要、处理过程记录自动生成能力

### 预诊断与自动化闭环
- 打通工单系统与诊断工具链(集群健康检查、日志分析、配置核查)
- 建设"工单进入即预诊断"的自动化链路，输出诊断报告供专家复用
- 实现标准场景(配额调整、证书更新、常见配置问题)的自动化闭环
- 设计人机协作交互(置信度分级：自动回复/建议采纳/仅供参考)
- 建设升级机制(复杂单精准路由至对应产品专家)

### 工单语料工程
- 主导历史工单数据的清洗、脱敏与结构化语料建设
- 设计工单语料Schema(问题现象/产品域/诊断路径/根因/解法/客户确认)
- 建设高质量FAQ与解决方案知识库的抽取-审核-发布流水线
- 构建工单场景SFT语料与评测集(分类准确率/解答采纳率)
- 建立语料飞轮机制(新工单结案自动回流为候选语料)

### 工单系统平台建设
- 参与工单系统核心链路研发(SLA管理/流转引擎/多渠道接入)
- 建设工单数据分析体系(热点问题、产品质量反哺、专家效能)
- 开发工单与ChatOps、值班系统、变更系统的集成
- 保障工单数据安全与客户隐私合规

### 效果运营与迭代
- 定义并追踪核心指标(自助解决率/预诊断命中率/平均结单时长)
- 分析Bad Case并推动Prompt、知识库、工具链的持续优化
- 与技术服务专家共建评审机制，保障智能回复质量

## 面试准备建议

### 高频面试题
1. **分诊设计**：工单智能分诊的准确率如何保障？分类体系变更(新产品上线)时如何低成本适配？
2. **预诊断链路**：设计"工单创建即触发预诊断"的完整链路，如何决定调用哪些诊断工具？超时与失败如何兜底？
3. **语料飞轮**：结案工单如何自动沉淀为语料？如何设计审核机制防止错误解法污染知识库？
4. **置信度分级**：智能回复何时直接发给客户、何时仅供专家参考？阈值如何标定与迭代？
5. **脱敏合规**：工单中包含客户IP、账号、日志敏感信息，语料化时如何设计脱敏流水线并保持诊断价值？
6. **效果度量**：自助解决率提升可能来自智能体也可能来自产品改进，如何设计归因分析？

### 系统设计题
- 设计一个支撑百万级工单/年的智能工单系统架构(含SLA与升级机制)
- 设计工单语料库Schema与"结案→候选语料→审核→发布"流水线
- 设计工单智能体与运维诊断工具链(MCP)的集成方案
- 设计多租户场景下的知识库隔离与共享机制

### 实操考察
- 分析一条真实技术工单对话，抽取结构化诊断信息
- 编写Prompt完成工单分类+信息补全追问的设计
- Python实现相似工单检索的简单方案并讨论优化方向
