# 检查清单：开一个新 agent 会话前

新会话的 agent 没有你的上下文。开跑前 2 分钟准备这几项，能省掉之后 20 分钟的来回。

## 任务侧

- [ ] **一句话目标**：做成什么样算完成？（写不出这句话 = 任务还没想清楚，先用[任务拆解](../../skills/task-decomposition/SKILL.md)）
- [ ] **验收标准可自查**：测试命令 / 页面行为 / 构建结果，agent 能独立执行并汇报。
- [ ] **范围边界**：明确"只动哪些、不许动哪些"。这是防止 agent 跑偏最有效的一句话。
- [ ] **相关入口已备好**：文件路径、报错原文、需求链接——直接贴，不要让 agent 先找 10 分钟。

## 环境侧

- [ ] 工作区干净：`git status` 无未提交改动（agent 的改动才清晰可辨）。
- [ ] 在正确的分支上，且分支命名说得通。
- [ ] 测试基线已知：全绿？还是有本来就红的？（避免把存量问题算到这次头上）
- [ ] 项目有 AGENTS.md / CLAUDE.md 等约定文件时，确认内容仍然准确。

## 会话侧

- [ ] 大任务先要**计划再要代码**：让 agent 先列实现步骤，你确认方向后再动手。
- [ ] 说清输出偏好：要证据（文件:行号）、不要重写整段、不确定要问。
- [ ] 这类任务以前做过吗？有旧会话/文档可引用就贴过来，别让 agent 从零推理。

## 反面信号（出现任何一条，先停下来）

- 你说不出"验收标准"是什么 → 回到任务侧第一条。
- 你自己都没跑过这个项目 → 先走[接手仓库流程](../workflows/onboarding-a-new-repo.md)。
- 你打算"让它试试看" → 花两分钟把预期写清楚，比事后返工便宜。
