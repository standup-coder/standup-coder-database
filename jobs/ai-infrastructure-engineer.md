# AI基础设施工程师职位描述(JD)

## 岗位基本信息
- **岗位名称**：AI基础设施工程师(AI Infrastructure Engineer / GPU Cluster Engineer)
- **产业链定位**：AI产业链上游 - 算力基础设施层
- **工作性质**：全职
- **工作地点**：北京/上海/深圳/杭州/贵阳/乌兰察布(数据中心)

- **薪资范围**：30K-80K/月
- **团队规模**：AI Infra团队30-200人，集群运维/调度组8-25人

## 公司与行业背景

### 行业背景
AI基础设施是大模型时代的"水电煤"。万卡级GPU集群的建设与运维、算力利用率(MFU)的提升、以及智算中心的规模化交付，构成了这一岗位的核心价值场景。2025年以来国家"东数西算"工程推进、各地智算中心密集落地，加之国产算力集群的异构混合调度需求，使AI Infra岗位从"运维支撑"角色升级为"决定训练成败"的核心工程角色。

## 岗位职责

### GPU集群建设与运维
- 负责千卡/万卡级GPU集群的规划、部署与扩容
- 完成GPU服务器、InfiniBand/RoCE网络、并行存储的选型与验收
- 建设GPU驱动、CUDA、NCCL等基础软件栈的标准化镜像与版本管理
- 实施集群健康巡检、慢节点识别与自动隔离机制
- 保障集群可用性SLA(通常要求99.5%以上有效训练时长)

### 高性能网络与存储
- 设计并调优RDMA网络(InfiniBand/RoCEv2)拓扑与参数
- 完成NCCL通信性能测试与调优(AllReduce带宽达标验证)
- 部署并优化并行文件系统(Lustre/GPFS/JuiceFS/CPFS)
- 优化训练数据加载链路，消除IO瓶颈
- 建设Checkpoint读写加速方案(万卡Checkpoint秒级保存)

### 训练任务调度平台
- 基于Kubernetes + Volcano/Kueue构建AI任务调度平台
- 实现Gang Scheduling、拓扑感知调度、抢占与配额管理
- 开发多租户资源隔离与GPU虚拟化(MIG/vGPU/HAMi)方案
- 建设任务排队、优先级和资源超卖策略
- 支撑弹性训练(Elastic Training)与断点续训

### 稳定性与故障处理
- 建设GPU故障(XID报错/ECC错误/掉卡)的自动检测与替换流程
- 实现训练任务的自动故障恢复(Fault Tolerance)
- 定位并解决Hang、慢节点、通信超时等疑难问题
- 建设全链路可观测体系(GPU利用率/温度/功耗/网络/存储)
- 参与重大故障复盘与预防机制建设

### 效率与成本优化
- 分析并提升集群整体算力利用率(MFU/GPU Utilization)
- 优化训练作业的并行策略配置建议(TP/PP/DP/EP)
- 实施混部、潮汐调度以提升资源利用率
- 完成算力成本核算与优化方案输出
- 推动国产算力芯片的适配与混合异构调度

## 面试准备建议

### 高频面试题
1. **MFU分析**：万卡训练MFU只有35%，如何系统性定位瓶颈？分别从计算、通信、存储、调度四个维度展开。
2. **NCCL调优**：AllReduce带宽达不到理论值的70%，可能有哪些原因？如何验证？
3. **慢节点识别**：训练任务整体变慢但无报错，如何快速定位是哪张卡/哪台机器的问题？
4. **故障自愈设计**：万卡训练中单卡掉卡，如何设计自动摘除+任务恢复流程，把损失控制在分钟级？
5. **Gang Scheduling**：为什么AI训练必须用Gang调度？如何避免资源死锁和碎片化？

### 系统设计题
- 设计一个支持万卡规模、多租户的AI训练调度平台
- 设计GPU集群的全链路可观测与告警体系
- 设计万卡级Checkpoint的高速读写方案
- 设计异构算力(NVIDIA+国产)的统一纳管与调度架构

### 实操考察
- Linux性能问题排查现场演练
- K8s故障场景排查(Pod Pending/OOM/网络不通)
- GPU故障码解读(XID 13/31/48/79等)

### 面试流程
1. **HR初筛**(30分钟)
2. **技术一面**(1小时)：Linux + K8s + GPU基础
3. **技术二面**(1-1.5小时)：项目深挖 + 故障排查场景题
4. **技术三面**(1小时)：系统设计 + 架构思路
5. **交叉面**(1小时)：算法团队或平台团队协作评估
6. **HR终面**：整体周期2-3周
