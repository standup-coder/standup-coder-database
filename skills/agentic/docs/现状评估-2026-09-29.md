# 现状评估 · newbee 仓库（2026-09-29）

> 评估对象：`standup-coder/newbee`（暖床骑士 / obee，前身 coder.learnpack）
> 结论先行：**仓库处于停滞状态**——2013 年立项，2014 年导入 WeCenter 3.0.2 后 11 年无实质开发；设计文档全部是空壳占位符，代码零定制。
> 本评估是新项目 [agentic-newbee](../README.md) 的直接动因。

## 项目是什么

**newbee / obee（暖床骑士）**——"有爱的码农社区"，定位帮编程新人匹配导师。仓库实际内容只有两块：

- `web/doc/` 下 5 份设计文档（立项说明、需求说明书、交互原型设计、数据库设计、详细设计）**全部是占位符**，每份只有 4 行 "appsforcoder.com – Website for appsforcoder studio"，没有任何真实内容。
- `web/server/` 是 **WeCenter 3.0.2**（2014-12-05 build）完整源码，zip（4.9MB）和解压后 UPLOAD（21MB）**双份提交**。PHP 5.x + Zend Framework 1 + Savant3 + jQuery 的问答社区系统。

## 风险清单

1. **技术栈已死**：PHP 5.x + Zend Framework 1（EOL）+ 2014 年 jQuery；WeCenter 官方停止维护；PHP 8 下基本跑不起来，且这类老系统有大量已知 XSS / SQL 注入漏洞。
2. **敏感配置入库**：`config.inc.php` 提交了安装生成的加密 key；`install/` 目录完整保留。
3. **仓库冗余**：zip 与解压内容双份提交（约 26MB）；`.gitignore` 仅一行 "test"，形同虚设，.DS_Store 曾长期入库。
4. **工作区杂物**：`.mimosa/`、`.v2c/`、`.video_agent/` 为本地工具目录（untracked）；根目录 `.project` 是空 Eclipse 工程文件遗留物。

## 教训（新项目的立项约束）

1. **不放空壳文档**：newbee 的 5 份文档全部是 4 行占位符。新项目只写有真实内容的文档，宁缺毋滥。
2. **不引入改不动的第三方底座**：整包导入 20 万行不理解的代码 = 项目死亡起点。新项目技术栈保持小而主流，依赖数到个位数。
3. **MD 为唯一真值**：语料是 Markdown 本身，Web 只是渲染层——保证 Web 死了语料还活着。
4. **git 卫生从第一天做起**：合格的 .gitignore、不提交产物与密钥、干净的初始提交。
