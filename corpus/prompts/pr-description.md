# 提示词模板：让 agent 生成 PR 描述

## 何时用

改动完成、准备发 PR 时。让 agent 读 diff 生成初稿，你核对后微调——比从空白开始写快，也比 agent 直接提交给你的更可信。

## 模板

```text
请根据下面的 diff 生成 PR 描述，供人审核后使用：

<粘贴 git diff main...HEAD 或给出 commit 范围>

格式要求：
## 为什么改
<1-3 句：动机与背景，从需求/issue 角度写>
## 改了什么
<要点列表：按模块分组，写行为变化不写代码细节>
## 怎么验证的
<列出实际执行过的验证：测试命令与结果 / 手动验证步骤>
## 风险与回滚
<可能的副作用；出问题时的回滚方式>
要求：
- 只描述 diff 里真实存在的变化，禁止推测未做的事
- "怎么验证的"一节只写实际执行过的验证，没执行过的写"未验证：<原因>"
```

## 变量说明

| 变量 | 说明 |
| --- | --- |
| diff 范围 | 用 `main...HEAD`（三点）拿到分支独有改动 |
| 格式要求 | 固定四段式的好处：reviewer 最关心的"为什么"和"怎么验证"不会缺席 |

## 提示

- 最大的坑是 agent 把"计划做"写成"已做"。模板里两条"禁止"就是针对这个——收到后逐条核对，尤其"怎么验证的"。
- 顺手让 agent 检查 diff 里有没有混入无关改动（调试代码、临时文件），见[提交前检查清单](../checklists/before-commit.md)。
