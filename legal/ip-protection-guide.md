# 知识产权保护实务指南

## 1. 概述

知识产权是科技企业的核心资产。本指南覆盖专利、商标、著作权、商业秘密四大类型在科技行业的实务应用，帮助企业和开发者建立完整的知识产权保护体系。

| 知识产权类型 | 保护对象 | 保护期限 | 取得方式 | 主管部门 |
|--------------|----------|----------|----------|----------|
| **发明专利** | 技术方案、算法创新 | 20年 | 申请+审查 | 国家知识产权局 |
| **实用新型** | 产品结构改进 | 10年 | 申请（形式审查） | 国家知识产权局 |
| **外观设计** | 产品外观、UI界面 | 15年 | 申请（形式审查） | 国家知识产权局 |
| **商标** | 品牌标识、名称 | 10年（可续展） | 申请+审查 | 国家知识产权局 |
| **著作权** | 软件代码、文档、作品 | 作者终生+50年 | 自动取得（可登记） | 国家版权局 |
| **商业秘密** | 技术秘密、经营信息 | 无期限（保密即有效） | 自行保护 | 市场监管/法院 |

## 2. 专利保护实务

### 2.1 三种专利类型对比

| 对比项 | 发明专利 | 实用新型 | 外观设计 |
|--------|----------|----------|----------|
| **保护对象** | 方法、产品、算法 | 产品形状/结构 | 外观、图案、色彩 |
| **审查方式** | 实质审查 | 形式审查 | 形式审查 |
| **授权周期** | 18-36个月 | 6-12个月 | 4-8个月 |
| **保护期限** | 20年 | 10年 | 15年 |
| **年费** | 较高（逐年递增） | 中等 | 较低 |
| **适用场景** | 核心算法、架构创新 | 硬件结构改进 | UI设计、图标 |

### 2.2 专利申请流程

```text
发明专利申请流程：
技术交底书 → 专利检索 → 撰写申请文件 → 提交申请 → 初步审查
→ 公开（18个月）→ 实质审查 → 授权/驳回 → 年费维持

关键时间节点：
- 优先权期限：12个月（国内优先权）
- 实审请求：申请日起3年内
- 答复审查意见：4个月（可延期2个月）
```

### 2.3 专利布局策略

- **核心专利**：保护基础算法和架构，申请发明专利
- **外围专利**：围绕核心技术的应用场景，形成专利组合
- **防御专利**：针对竞争对手可能的技术路线提前布局
- **UI专利**：对创新交互设计申请外观设计专利
- **国际布局**：通过PCT途径进入目标市场国家

### 2.4 专利侵权应对

**发现侵权时：**
1. 证据固定：公证购买侵权产品、网页截图公证
2. 侵权比对：委托专利代理师出具侵权比对意见
3. 发送警告函：要求停止侵权并赔偿
4. 行政投诉：向地方知识产权局投诉
5. 提起诉讼：向有管辖权的法院起诉

**被诉侵权时：**
1. 核实专利权有效性（是否缴纳年费、是否过期）
2. 提起专利无效宣告请求
3. 进行不侵权抗辩或现有技术抗辩
4. 评估和解可能性

## 3. 软件著作权保护

### 3.1 软件著作权登记

- **登记机关**：中国版权保护中心
- **所需材料**：源代码（前后各30页）、软件说明书、申请表
- **审查周期**：普通30-60个工作日，加急1-5个工作日
- **费用**：官费免费（2024年起），加急需额外费用
- **效力**：登记证书是权属初步证据，非权利取得要件

### 3.2 开源协议合规

| 许可证 | 传染性 | 商用限制 | 核心义务 | 典型项目 |
|--------|--------|----------|----------|----------|
| **MIT** | 无 | 无 | 保留版权声明 | React、Vue |
| **Apache 2.0** | 无 | 无 | 保留声明+NOTICE | Kubernetes、Android |
| **GPL 3.0** | 强传染 | 无 | 衍生作品必须开源 | Linux内核、GCC |
| **AGPL 3.0** | 最强（网络触发） | 无 | 网络服务也需开源 | MongoDB(旧)、Grafana |
| **LGPL** | 弱传染（库级别） | 无 | 修改库需开源，调用不要求 | Qt、FFmpeg部分 |
| **BSD** | 无 | 无 | 保留声明，不得用作者名推广 | FreeBSD、Nginx(旧) |

**GPL传染性风险防范：**
- 商业闭源产品避免直接链接GPL库
- 使用GPL工具编译不触发传染（如GCC编译）
- 通过进程间通信(IPC)隔离GPL组件
- 建立开源组件准入审批流程

### 3.3 代码抄袭维权

**证据收集：**
- 代码相似度鉴定（委托司法鉴定机构）
- 接触可能性证明（前员工、合作方）
- 独创性表达比对（排除公共领域代码）
- Git提交记录、开发日志

**维权路径：**
1. 发送律师函要求停止使用
2. 向版权行政管理部门投诉
3. 提起著作权侵权诉讼
4. 涉及商业秘密的可同时主张商业秘密侵权

## 4. 商标保护实务

### 4.1 注册流程与类别选择

**注册流程：** 商标查询 → 提交申请 → 形式审查(1个月) → 实质审查(4-6个月) → 公告(3个月) → 注册证下发

**科技企业核心类别：**
| 类别 | 内容 | 必要性 |
|------|------|--------|
| 第9类 | 软件、App、电子设备 | 必注册 |
| 第42类 | SaaS、技术服务、软件开发 | 必注册 |
| 第35类 | 广告、商业管理、电商 | 强烈建议 |
| 第38类 | 通信服务、即时通讯 | 视业务而定 |
| 第41类 | 教育、培训、娱乐 | 视业务而定 |

### 4.2 域名与品牌保护

- **域名注册**：注册.com/.cn/.net等主要后缀，防御性注册近似域名
- **社交媒体**：统一注册微信公众号、微博、抖音等账号名称
- **监测预警**：定期监测商标公告，及时提出异议
- **跨境保护**：在目标市场国提前注册商标（马德里体系或逐一注册）

## 5. 商业秘密保护

### 5.1 商业秘密认定三要件

1. **秘密性**：不为公众所知悉（非公开渠道可获取）
2. **价值性**：具有商业价值（能带来竞争优势）
3. **保密性**：权利人采取了合理保密措施

### 5.2 保密协议(NDA)设计要点

- **保密信息定义**：明确列举+兜底条款，避免过于宽泛
- **保密期限**：在职期间+离职后2-5年（技术秘密可更长）
- **保密义务**：不得披露、不得用于非工作目的、离职时归还/销毁
- **违约责任**：约定违约金+实际损失赔偿
- **例外情形**：公开信息、独立开发、法律强制披露

### 5.3 离职员工泄密防范

- **离职面谈**：提醒保密义务存续，确认归还所有资料
- **设备检查**：离职前检查工作设备是否有异常拷贝行为
- **权限回收**：离职当日关闭所有系统权限
- **竞业配合**：对核心人员启动竞业限制（参见竞业协议指南）
- **持续监测**：关注离职员工新单位是否出现相似技术/产品

## 6. 开源合规管理

### 6.1 开源许可证选择指南

| 企业诉求 | 推荐许可证 | 理由 |
|----------|------------|------|
| 最大化传播，不限制使用 | MIT / Apache 2.0 | 无传染性，商业友好 |
| 要求衍生作品开源 | GPL 3.0 | 强传染，保护开源生态 |
| 网络服务也需开源 | AGPL 3.0 | 堵住SaaS漏洞 |
| 库被调用不传染，修改需开源 | LGPL | 平衡商业使用和开源贡献 |
| 专利保护+宽松使用 | Apache 2.0 | 含明确专利授权条款 |

### 6.2 开源审计工具

| 工具 | 类型 | 特点 |
|------|------|------|
| **FOSSA** | 商业SaaS | 自动化扫描、许可证合规、漏洞检测 |
| **Black Duck** | 商业 | 企业级SCA，深度代码片段匹配 |
| **Snyk** | 商业+免费层 | 开发者友好，CI/CD集成 |
| **ScanCode** | 开源 | 免费，许可证和版权检测 |
| **OWASP Dependency-Check** | 开源 | 侧重安全漏洞 |

### 6.3 企业开源合规流程

1. **准入审批**：引入开源组件前评估许可证兼容性
2. **SBOM管理**：维护软件物料清单，记录所有依赖及版本
3. **定期扫描**：CI/CD流水线集成许可证扫描
4. **合规发布**：按许可证要求附带声明、源码或NOTICE文件
5. **贡献管理**：员工对外贡献代码需经内部审批（CLA签署）

## 7. AI生成内容的知识产权问题

### 7.1 AI作品著作权归属

- **现行规则**：北京互联网法院(2023)判例认定，人类对AI生成内容做出实质性智力贡献时，可享有著作权
- **关键因素**：提示词设计的独创性、参数调整的创造性、后期编辑的程度
- **企业建议**：保留AI创作过程记录（提示词、迭代版本），证明人类智力投入

### 7.2 AI训练数据版权争议

- **合理使用抗辩**：目前中国法律未明确AI训练是否构成合理使用
- **风险防控**：使用授权数据集、公开许可数据、自有数据训练
- **行业趋势**：部分平台已推出AI训练授权许可机制
- **合规建议**：建立训练数据来源台账，标注授权依据

### 7.3 AIGC标识义务

- AI生成的文本、图片、音频、视频需添加显著标识
- 深度合成内容（换脸、配音）需双重标识（显著+隐式水印）
- 服务提供者应在用户协议中明确标识义务
- 违反标识义务可被处以警告、罚款、暂停服务

## 8. 维权实务操作

### 8.1 侵权证据固定

| 证据类型 | 固定方式 | 注意事项 |
|----------|----------|----------|
| **网页侵权** | 公证处网页保全/可信时间戳 | 录屏+截图，显示完整URL和时间 |
| **软件侵权** | 公证购买+司法鉴定 | 保留安装包、运行界面 |
| **专利侵权** | 公证购买产品+技术比对 | 保留购买凭证和产品实物 |
| **商业秘密** | 服务器日志+取证 | 及时保全，防止证据灭失 |
| **商标侵权** | 公证购买+拍照 | 保留发票、包装、宣传材料 |

### 8.2 行政投诉 vs 司法诉讼

| 对比项 | 行政投诉 | 司法诉讼 |
|--------|----------|----------|
| **受理机关** | 市场监管局/知识产权局 | 人民法院 |
| **处理速度** | 快（1-3个月） | 慢（6-18个月） |
| **赔偿支持** | 不支持（仅处罚） | 支持损害赔偿 |
| **执行力度** | 行政处罚、没收销毁 | 判决+强制执行 |
| **适用场景** | 快速制止侵权 | 追求经济赔偿 |
| **费用** | 低 | 较高（律师费+诉讼费） |

### 8.3 赔偿计算方式

1. **实际损失**：权利人因侵权减少的利润
2. **侵权获利**：侵权人因侵权获得的利润
3. **许可费倍数**：参照合理许可使用费的1-5倍
4. **法定赔偿**：著作权500-500万元；专利3万-500万元；商标50万以下
5. **惩罚性赔偿**：故意侵权且情节严重，可判1-5倍惩罚性赔偿

### 8.4 诉前禁令（行为保全）

- **适用条件**：不立即制止将造成难以弥补的损害
- **担保要求**：通常需提供相当于可能损失的担保
- **审查时间**：48小时内裁定（紧急情况）
- **实务建议**：证据充分时优先申请，可有效阻止侵权扩大

## 9. 企业知识产权管理建议

### 9.1 制度建设

- 建立知识产权管理制度（可参照GB/T 29490贯标）
- 入职时签署知识产权归属协议和保密协议
- 建立发明创造奖励制度（职务发明报酬）
- 定期进行知识产权审计和风险评估

### 9.2 日常注意事项

- 代码提交前检查是否包含第三方专有代码
- 技术文章发表前评估是否影响专利申请（新颖性）
- 产品命名前进行商标检索
- 合作开发前明确知识产权归属
- 参加技术会议注意保密信息的披露范围
