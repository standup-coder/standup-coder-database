# ATS简历优化与求职信撰写指南

## 一、ATS是什么

### Applicant Tracking System（申请人追踪系统）
ATS是企业用于管理招聘流程的软件系统，在简历到达HR手中之前，先由ATS进行自动化筛选和排序。

### 工作原理
1. **解析**：将简历文件（PDF/DOCX）转换为结构化数据
2. **匹配**：将候选人信息与职位JD中的关键词进行比对
3. **评分**：根据匹配度、经验年限、技能等维度打分
4. **排序**：按分数排列，HR通常只看前20-30%的简历

### 淘汰率
- 超过75%的简历被ATS过滤，HR从未看到
- 大型企业（500人+）几乎100%使用ATS
- 常见ATS系统：Workday、Greenhouse、Lever、iCIMS、Taleo

### 主流ATS解析差异
- Workday：对格式要求较宽松，支持多栏
- Taleo（Oracle）：解析能力较弱，格式要求严格
- Greenhouse/Lever：相对友好，但仍建议简洁格式

## 二、ATS友好格式

### 必须遵守的规则

| 规则 | 说明 |
|------|------|
| 单栏布局 | 多栏可能导致解析顺序错乱 |
| 无表格 | 表格内容常被ATS忽略或错位 |
| 无图片/图标 | 图片中的文字无法被解析 |
| 标准字体 | Arial, Calibri, Times New Roman, Helvetica |
| 标准Section名 | Experience, Education, Skills（不要写"Where I've Been"） |
| 无页眉页脚 | 部分ATS不读取页眉页脚内容 |
| 文件格式 | 优先DOCX，其次PDF（确认ATS支持） |
| 字号 | 正文10-12pt，标题14-16pt |

### 安全的格式元素
- 项目符号（bullet points）：使用标准圆点
- 加粗/斜体：用于强调，ATS可识别
- 分隔线：简单的水平线
- 日期格式：Month Year（如"Jan 2024 - Present"）

### 避免的格式元素
- 文本框/浮动元素
- 图表、进度条（技能评级）
- 特殊字符和emoji
- 复杂排版（杂志风格）
- 扫描件/图片格式简历

## 三、关键词优化

### 从JD提取关键词
1. 仔细阅读职位描述，标记所有技术名词
2. 区分硬性要求（Must-have）和加分项（Nice-to-have）
3. 注意重复出现的词汇（权重更高）
4. 提取软技能关键词（leadership, cross-functional）

### 自然嵌入策略
- 在Experience的bullet point中自然使用关键词
- 不要简单罗列（"Java, Python, Go, React..."单独一行不够）
- 结合具体场景："Built microservices using **Java** and **Spring Boot**, deployed on **Kubernetes**"
- 在Summary/Objective中融入核心关键词

### 技能Section
- 单独设置"Technical Skills"或"Skills"section
- 按类别分组：Languages / Frameworks / Tools / Cloud
- 包含JD中出现的所有相关技能（即使只是了解）

### 同义词与变体
- 同时使用全称和缩写：Machine Learning (ML)
- 使用不同表述：REST API / RESTful API
- 包含新旧名称：JavaScript (ES6+) / TypeScript
- 云平台变体：AWS / Amazon Web Services

## 四、量化成果

### 公式
```
[Action Verb] + [Task/Project] + [Result] + [Metric]
```

### 示例对比
```
❌ "Responsible for improving website performance"
✅ "Optimized frontend bundle size by 60% (2.1MB → 840KB) through code splitting
    and lazy loading, reducing page load time from 4.2s to 1.8s"

❌ "Worked on database optimization"
✅ "Redesigned PostgreSQL query patterns and added composite indexes,
    reducing API P99 latency from 800ms to 120ms for 3M+ daily requests"

❌ "Led a team of developers"
✅ "Led a cross-functional team of 8 engineers to deliver a payment platform
    2 weeks ahead of schedule, processing $2M+ in daily transactions"
```

### 量化维度
- 性能提升：延迟降低X%、吞吐量提升X倍
- 规模指标：DAU/MAU、QPS、数据量
- 效率提升：开发时间缩短、部署频率提高
- 业务影响：收入增长、成本节约、转化率提升
- 团队贡献：带领X人、Code Review X个PR/周

### 每段经历建议
- 每个职位2-4个bullet point
- 每个bullet至少包含1个数字
- 最重要的成就放第一条

## 五、行业定制

### 互联网/科技公司
- 强调技术栈和项目复杂度
- 突出规模指标（用户量、并发量）
- 包含开源贡献和技术博客
- 简历长度：1-2页

### 金融行业
- 强调合规、安全、高可用
- 突出系统稳定性和风控经验
- 使用金融术语（P&L、Risk、Compliance）
- 格式更正式保守

### 外企
- 英文简历，简洁直接
- 强调跨文化协作和英语能力
- 突出Impact和Ownership
- 不需要照片、年龄、婚姻状态

### 国企/央企
- 中文简历，格式规范
- 强调学历、政治面貌、稳定性
- 项目经验突出规模和级别
- 可包含获奖和证书

### 创业公司
- 强调全栈能力和快速学习
- 突出从0到1的经验
- 展示多面手特质（技术+产品+运营）
- 简历可以更个性化

## 六、中英文简历对比

| 维度 | 中文简历 | 英文简历 |
|------|----------|----------|
| 长度 | 1-2页 | 1页（初级）/ 2页（高级） |
| 照片 | 常见（尤其国企） | 不需要（欧美） |
| 个人信息 | 可含年龄、性别、婚姻 | 仅姓名、电话、邮箱、LinkedIn |
| 语气 | 较含蓄 | 直接、自信 |
| 动词 | "负责..."、"参与..." | "Led"、"Architected"、"Reduced" |
| 教育 | 详细（含课程） | 简洁（学校+学位+年份） |
| 格式 | 可稍花哨 | 简洁专业 |

### 英文简历注意事项
- 使用过去时态描述已完成的工作
- 避免代词"I"（直接以动词开头）
- 数字使用阿拉伯数字
- 不要翻译公司名（保留官方英文名）

## 七、求职信（Cover Letter）

### 结构（300字以内）

**第一段：开头（2-3句）**
- 说明申请什么职位、从哪里看到
- 用一句话表达为什么对这个公司/职位感兴趣
- 例："I'm excited to apply for the Senior Backend Engineer role at [Company]. Having followed your engineering blog on distributed systems, I'm eager to contribute to challenges at your scale."

**第二段：匹配（3-4句）**
- 选取JD中2-3个核心要求
- 用具体经历证明你匹配
- 量化成果
- 例："At [Previous Company], I designed a real-time data pipeline processing 500K events/sec using Kafka and Flink — directly relevant to your streaming platform initiative."

**第三段：价值 + CTA（2-3句）**
- 说明你能带来什么独特价值
- 表达进一步沟通的意愿
- 例："I'd welcome the opportunity to discuss how my experience in high-throughput systems can accelerate [Company]'s platform roadmap. Thank you for your consideration."

### 关键原则
- 每封求职信必须定制（不要群发同一封）
- 不要重复简历内容，而是补充"为什么"
- 展示对公司的了解（产品、技术、文化）
- 语气自信但不傲慢
- 300字以内，3-4段

## 八、常见错误

### 格式错误
- 使用花哨模板（双栏、彩色、图标）
- 文件命名不规范（"resume_final_v3.pdf"）
- 正确命名：FirstName_LastName_Resume.pdf

### 内容错误
- 信息过载：写了10年前的无关经历
- 拼写/语法错误（尤其英文简历）
- 使用模糊表述："responsible for various tasks"
- 包含无关信息：兴趣爱好（除非高度相关）
- 简历与JD完全不匹配（海投同一份）

### 策略错误
- 只投不优化：每份简历都应针对JD微调
- 忽略关键词：ATS无法识别你的技能
- 过度包装：面试时无法自圆其说
- 遗漏联系方式或链接失效

## 十、投递前10项必查清单

- [ ] **格式检查**：单栏、无表格图片、标准字体、DOCX/PDF格式
- [ ] **关键词匹配**：对照JD确认核心关键词已包含（至少80%匹配）
- [ ] **量化成果**：每段经历至少有1-2个数字
- [ ] **动词开头**：每条bullet以强动词开始（非"负责"）
- [ ] **无拼写错误**：用工具检查+人工通读
- [ ] **联系方式正确**：电话、邮箱、LinkedIn/GitHub链接可访问
- [ ] **Section名称标准**：Experience / Education / Skills / Projects
- [ ] **长度适当**：初级1页，高级最多2页
- [ ] **文件命名规范**：Name_Position_Resume.pdf
- [ ] **针对性定制**：确认这份简历是为这个职位优化的

## 十一、ATS测试方法

1. 将简历上传到Jobscan，对比目标JD查看匹配分数
2. 将PDF简历复制粘贴到纯文本编辑器，检查内容是否完整
3. 用不同ATS模拟器测试解析结果
4. 请朋友用不同设备打开，确认格式一致
5. 目标：Jobscan匹配度达到80%以上再投递
