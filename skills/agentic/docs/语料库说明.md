# 语料库说明 · corpus/

语料库是本项目的第一真值：**Markdown 文件本身就是产品**，Web App 只是渲染层。写作与维护规则如下。

## 目录与用途

```
corpus/
├── prompts/      # 可复用提示词模板
├── workflows/    # 完整工作流（步骤 + 判据 + 坑）
├── transcripts/  # 示例对话节选与复盘（教学用）
└── checklists/   # 动作前检查清单
```

## frontmatter 规范

每篇语料以 YAML frontmatter 开头：

```yaml
---
title: 提示词模板：把模糊需求变成清晰任务
category: prompts        # prompts | workflows | transcripts | checklists
tags: [任务拆解, 提问]
updated: 2026-09-29
---
```

- `title`：中文标题，网页列表与详情页标题来源。
- `category`：必须等于所在目录名。
- `tags`：2–5 个，用于过滤与关联。
- `updated`：实质内容变更时更新。

## 写作红线

1. **有真实内容才建文件**——没有实质内容的主题就先不建（newbee 的 5 份空壳文档是反例）。
2. 单篇正文 30–120 行；超过就拆成两篇，用站内链接互引。
3. 提示词模板必须给出：**何时用 / 模板正文 / 变量说明**，且模板可直接复制使用。
4. 示例对话必须开头声明"教学用示例，非真实日志"，不得虚构为真实记录。
5. 站内链接用相对路径（如 `../workflows/tdd-loop-with-agent.md`），校验脚本会检查可达性。

## 校验

```bash
npm --prefix webapp run corpus:check
```

检查项：frontmatter 必填字段、category 与目录一致、站内相对链接可达、正文行数红线。接入 CI 前先手动跑。
